# FLOY-NEW — стандарти коду

Nuxt 3 + Vue 3 (SSR) фронтенд floy.com.ua. Працюй **завжди** за принципами нижче.
Портативний Node 22 у `.node/` — для будь-яких npm/nuxt команд спершу додай його в PATH
(`C:\Web-SERVER\domains\FLOY-NEW\.node\node-v22.14.0-win-x64`). Системний Node 16 не чіпати.

Загальне правило: **спершу шукай наявний примітив (токен/клас/компонент/composable) і перевикористай його.
Створюй нове — лише коли нічого не підходить, і одразу роби його перевикористовуваним.**

## 0. Комунікація та робочий процес

- **Відповідай завжди українською мовою.**
- **Не запускай Build самостійно** (`build.cmd` / `nuxt build` / `nuxi build`) — це робить розробник вручну.
  Можеш редагувати код і пояснювати зміни, але збірку для перевірки не запускай.

---

## 1. Стилі — тільки централізовано

- **Кольори, скруглення, відступи-константи, тіні, шрифт — лише через CSS-змінні** з `assets/css/main.css` (`:root`).
  Жодних літералів типу `#ff7a00`, `#14100b`, `99px`, `#fff` у компонентах.
  Потрібен новий колір/розмір → **додай токен** у `main.css`, не хардкодь.
  Чинні токени: `--bg*`, `--text*`, `--accent*`, `--on-accent`, `--bg-deep`, `--img-bg`,
  `--radius-sm|--radius|--radius-lg|--radius-pill`, `--shadow-*`, `--success/--danger/--warning`.
- **Перевикористовуй глобальні класи** з `main.css`: `.container`, `.btn`/`.btn-*`, `.card`, `.badge`,
  `.form-control`, `.typography`, `.section-title`, `.skeleton`, `.products-grid`, `.p-card*` (база картки товару),
  утиліти (`.text-muted`, `.visually-hidden` тощо). Не дублюй ці стилі в `scoped`.
- **Scoped-стилі не шаряться між компонентами.** Якщо стиль потрібен ≥2 компонентам — виноси базу в `main.css`,
  а в компоненті лишай лише його унікальні відмінності (приклад: `.p-card` у `main.css`, специфіка — у
  `ProductCard.vue` / `ProductCardPrintcase.vue`).

## 2. Без дублювання, масштабованість

- **Іконки — лише через `<AppIcon name="…" />`** (реєстр SVG у `components/AppIcon.vue`).
  Нова іконка = один запис у `ICONS`, не інлайн-`<svg>`. Підтримує `size`, `filled`, `stroke-width`, `solid`.
- **Зображення — лише через `<AppImage>`** (`components/AppImage.vue`, обгортка над `@nuxt/image`/IPX):
  WebP + адаптивний `srcset` + retina, з обходом IPX для SVG-плейсхолдерів. Не став «голий» `<img>` для фото товарів/категорій/статей.
- **Логіку — у composables** (`composables/`): API → `useShopApi`, URL/зображення/ціна → `useUrl`,
  SEO → `useSeo`, кошик/списки → `useCart`/`useLists`, хелпери товару → `useProductHelpers`. Не дублюй fetch/обчислення в сторінках.
- Компоненти — **малі, сфокусовані, керовані пропсами**, з типами через `defineProps<…>()`. DRY. Без «магічних» копіпаст.

## 3. SEO + заточеність під ШІ/AI-краулери

- **SSR-first**: увесь значущий контент має бути у server-rendered HTML (не лише на клієнті) — інакше його не бачать ні Google, ні AI-боти.
- **Кожна сторінка** викликає `usePageSeo({ title, description, image })` (canonical + OG + Twitter) і, де доречно, `useJsonLd(...)`.
- **Структуровані дані schema.org** (JSON-LD) — повні й коректні: `Product`/`Offer`, `ItemList`, `BreadcrumbList`,
  `Organization`, `WebSite`, `Article`/`BlogPosting`, за потреби `FAQPage`. Це головне джерело розуміння для AI-систем.
- **Семантичний HTML**: один `<h1>` на сторінку, логічна ієрархія `h2/h3`, `<nav>/<main>/<article>/<section>`,
  описові `alt` у зображень, осмислений текст посилань. Уникай div-супу.
- canonical + hreflang (`ru` без префікса, `uk` з `/uk`) тримай у консистентності з URL старого сайту.

## 4. Швидкість і компактність

- **Зображення**: `<AppImage>` усюди; нижче згину — lazy; LCP-зображення (головне фото товару, герой статті, 1-й банер) —
  `loading="eager" fetchpriority="high" preload`; завжди `width`/`height` (або `aspect-ratio`) проти CLS.
- **Дані**: паралельний `Promise.all([...useAsyncData...])` на SSR; стабільні ключі з локаллю; `null → false`, щоб не було повторних запитів на клієнті.
- Мінімум клієнтського JS; не тягни важкі залежності без потреби. Код — **компактний, типізований, читабельний**.
- Перед деплоєм: `build.cmd` (прод-білд з усіма оптимізаціями).

## 5. Стиль самого коду

- Коментарі — українською (як у наявному коді), короткі, по суті.
- Дотримуйся наявних патернів і форматування (табуляція, лапки, нейминг `kebab`-класів `block__element--modifier`).
- Перед редагуванням великого компонента — переконайся, що не вводиш літерал/дубль, який уже є токеном/класом/компонентом.
