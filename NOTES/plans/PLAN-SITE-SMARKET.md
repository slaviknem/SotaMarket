## 1. Як SMARKET пов'язаний з FLOY-NEW (одна логіка)

- **Дані — ті самі:** адмінка `admin.floy.com.ua`, запити з `?site=smarket`; правила даних однакові для всіх
  сайтів (`PLAN-MULTISITE.md` §5.0).
- **Код — копія FLOY-NEW з історією:** `upstream` = FLOY-NEW. Виправлення рушія з FLOY приходять так (ПК,
  PowerShell, `C:\Web-SERVER\domains\SMARKET`; злиття — це коміт, тож робить власник):
  ```powershell
  git fetch upstream
  git merge upstream/main
  ```
- **Що міняємо в SMARKET:**
  1. `brand/` — усе своє: `site.config.ts`, `theme.css`, `i18n/{uk,ru}.json` (перекриває будь-який ключ спільних
     текстів), `public/` (лого, фавікони, og, файл верифікації GSC), `robots.txt`;
  2. `brand/components/` — власні версії видимих компонентів з тими самими іменами (шапка, меню, футер,
     картки, блоки головної) — перекривають рушій (механізм — етап S1);
  3. серверне: `.env`, `ecosystem.config.cjs` (ім'я процесу, порт, кількість воркерів), `deploy.sh` (ім'я
     процесу, порт, кеш nginx).
- **Спільний код рушія** (composables, server, pages, решта components, `assets/css/main.css`) — не правити
  «під SMARKET». Якщо без зміни ніяк (перемикач розділу, слот, фільтр, світла тема) — зміна **загальна**: FLOY з
  нею лишається піксель у піксель. Кожну таку зміну — у §10 «Журнал змін рушія»: їх переносимо у FLOY-NEW
  (власник або окремий чат у FLOY-NEW), щоб копії не розходились і наступний `merge upstream/main` був чистим.
- Помилку рушія, знайдену в SMARKET, виправляємо так само — і в §10.

## 8. Сервер (пропозиція; деталі — `DEPLOY.md`)

- Клон `/root/nodeapps/SMARKET-PROD` (з `origin` SMARKET), процес PM2 `smarket-prod`, порт **3010** (зайняті
  3000–3003, 4000/4001, 9999), 2 воркери (`FLOY_WORKERS` — пам'ять сервера 26,8 з 30,5 ГБ), кеш nginx
  `/var/cache/nginx-smarket`; `interpreter`, `exec_mode: 'fork'`, `cluster.mjs` — не чіпати.
- **Без піддомена (рішення 22.10).** Перевіряємо в два кроки: (1) на ПК — dev проти живого API (усі екрани,
  SEO-зліпок, прогін адрес інвентаря); (2) на сервері — новий процес `smarket-prod` запускається на порту 3010
  **до** перемикання, публічно недоступний; Claude дає скрипт для сервера: `curl` з `Host: steklomarket.com.ua`
  на `127.0.0.1:3010` по списку адрес (коди, canonical, наявність товарів). Лише потім — nginx.
- **nginx vhost** steklomarket.com.ua: свій порт і кеш, ключ кешу без `Vary: Cookie`, `/img/` без `limit_conn`,
  www → без www, **без** `location` для robots. Старий процес Nuxt 2 не видаляти до кінця моніторингу — це відкат
  (повернути `proxy_pass` на старий порт і `nginx -s reload` — хвилина).

**Дані про трафік (бажано до перемикання; не обов'язково для роботи сайту):**
- **Логи nginx** — найпростіше: уже лежать на сервері, одна команда з `../inventory/README.md` («Від власника», п. 2)
  у FLOY-NEW, ~5 хвилин; показують, які адреси відвідує Google і куди приходять люди з пошуку.
- **Google Search Console** — безкоштовний кабінет Google про сайт у пошуку (search.google.com/search-console).
  Якщо steklomarket.com.ua там уже є — «Ефективність → Сторінки → Експортувати». Якщо немає — «Додати ресурс →
  Домен → steklomarket.com.ua» і підтвердити записом TXT у DNS (HestiaCP → DNS → steklomarket.com.ua; на старому
  сайті й у DNS підтвердження зараз немає — перевірено 22.10). Дані збираються з дня підтвердження — тому краще
  зареєструвати якомога раніше; після перемикання там же подати новий sitemap.
- **Аналітика** (GA4 / GTM / Pixel) — на старому сайті немає; не обов'язкова. Якщо захочете статистику
  відвідувань — створити ресурс GA4 (analytics.google.com → Адміністрування → Створити ресурс → веб-потік
