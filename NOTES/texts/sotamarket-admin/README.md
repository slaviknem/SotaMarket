# Тексти адмінки SotaMARKET (T6) — чернетки й SQL

Чернетки статей сайту `sotamarket` в адмінці (`articles`), мета моделей (`categories_text`) і шаблони тем-фільтрів
(`filters`). Зараз на sotamarket.com.ua «Про нас» — копія FLOY («Мы интернет-магазин «Floy»»), «Доставка» — FLOY із
самовивозом у Полтаві, «Повернення» немає (404), розділ «Чохли» описує шкіряні книжки й протиударні, яких у Sota немає,
хаб конструктора ru — українською, шаблону конструктора немає (усі `/printcase/{модель}` — `noindex`), у 8 тем описи
порожні. Усе збирається в один файл — `FLOY-ADMIN/NOTES/sql/sotamarket-texts-t6.sql`.

| `povernennya.{uk,ru}.html` | `/povernennya` | нова стаття (умови — як у FLOY: 14 днів, без дефекту / з дефектом, обмін до 7 днів, комісії); зв'язок — чат |

Код адмінки (той самий крок, деплой — власник): `app/Actions/Utilities/MetaTagsUtil.php` — кирилична назва з
`categories_text` сайту (її пише `CategoryAction::translateTitleRus` перед генерацією мети), порожня → повна назва
(`?:` замість `??`: колонки — рядки з `''` за замовчуванням). Без цього кожна нова модель Sota знову отримає
обрізаний title. Для FLOY і SMARKET змінюється лише мета **нових** моделей — з тією ж кириличною назвою, що й на сайті.

## Підтвердити власнику (до виконання)

1. **«Повернення»:** чохол з твоїм фото обмінюємо чи повертаємо лише за браку друку або пошкодження (так у SMARKET,
   погоджено 24.10); готові дизайни — за загальними правилами FLOY (14 днів, без слідів використання).
2. **Відправка — «зазвичай наступного робочого дня»** після підтвердження (як у текстах конструктора FLOY і SMARKET).
3. **Менеджер дзвонить і звіряє** модель і картинку кожного замовлення (а для свого фото — макет): так написано скрізь
   (плитка «Звіримо перед друком» на головній — з T1).
4. **Текст головної** — лишити старий з правками (як тут) чи переписати повністю (у ньому досі «у сучасному світі» й
   загальні слова; зате він в індексі).

## Як застосувати

1. Правки — у `*.html` / `meta.json` цієї теки або у файлі тем скіла, потім (ПК, PowerShell,
   `C:\Web-SERVER\domains\SOTAMARKET`):
   ```powershell
   $env:Path = "C:\Web-SERVER\domains\SOTAMARKET\.node\node-v22.14.0-win-x64;$env:Path"
   node NOTES/texts/sotamarket-admin/build-sql.mjs
   ```
   — перезбирає `FLOY-ADMIN/NOTES/sql/sotamarket-texts-t6.sql` (SQL руками не правити).
2. Виконати SQL на прод-базі адмінки (phpMyAdmin або `mysql`). Він сам робить бекап (`articles_bak_t6_20261104`,
   `filters_bak_t6_20261104`, `categories_text_bak_t6_20261104`), перевірки в кінці показують `0 0 0`, `7`, `0`, `8`;
   повторний запуск нічого не дублює; відкат — закоментований у кінці файла. Перевірено на MySQL 8.0 04.11 (тестова база
   з тими самими колонками й рядками трьох сайтів: два прогони, FLOY і SMARKET не змінено, ручна мета моделі не змінена,
   відкат повертає все до байта; база видалена); функції — лише ті, що є в MariaDB 10.6.
3. Адмінка → «Очистити кеш» (`/do/clear_cache`): статті, категорії й фільтри apisite кешуються.
4. Перевірка: `https://admin.floy.com.ua/apisite/articles/article/povernennya?site=sotamarket&lang=uk` — JSON зі
   статтею; `…/apisite/filters/filter/iphone-15/anime?site=sotamarket&lang=uk` — `description` з `#model#`;
   `…/apisite/categories/category/iphone-17-pro?site=sotamarket&lang=uk` — `meta_title` закінчується «на Айфон 17 Про».
   На dev Sota `/povernennya` — 200, `/uk/chekhly` (`h1` «Чохли з картинками для смартфонів»), `/uk/printcase/iphone-15`
   — без `noindex`, на `/iphone-15/filter/anime` — стаття під сіткою. Тест унікальності (ПК, з кореня SOTAMARKET) —
   `node scripts/uniq-check.mjs http://localhost:3011 https://floy.com.ua --only=…` і те саме з `https://steklomarket.com.ua`.
