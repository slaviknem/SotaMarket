# Власні компоненти бренду

Компонент тут з **тим самим іменем і тією ж вкладеністю**, що в `components/` рушія, перекриває рушійний
скрізь: `brand/components/AppHeader.vue` → `<AppHeader>`, `brand/components/blocks/PostsGrid.vue` →
`<BlocksPostsGrid>` і `<LazyBlocksPostsGrid>`. Механізм — `nuxt.config.ts` → `components` (тека бренду з
вищим `priority`); перевірено 22.10 (SSR, гідратація, `Lazy`, `hydrate-on-visible`).

Правила (`PLAN-MULTISITE.md` §3, §4.0, §4.4):
- **дизайн — окремо, логіка — спільна:** хочеться, щоб сайт виглядав інакше, — копія компонента сюди, а не
  правка рушія (FLOY її не бачить, переносити у FLOY нічого не треба); правка рушія — лише для логіки;
- лише видимі «обличчя» — шапка, футер, мобільне меню, блоки головної, картки; до ~12 на сайт;
  сервісні екрани (кошик, оформлення, підтвердження, конструктор) — спільні, лише тема;
- компонент бренду — шаблон і стилі; логіка лишається в composables рушія, пропси й події — ті самі,
  що в рушійного (його викликають ті самі сторінки);
- де логіки багато, рушій уже розділив її й вигляд — перекривати **вигляд**, логіку не копіювати:
  сторінка категорії (модель, бренд, розділ, фільтр, `/chekhly`) — `shop/CategoryView.vue`, дані й дії —
  `useCategoryPage()` (логіка — `ShopCategoryPage`); картка товару — `ProductCard.vue`, логіка —
  `useProductCard(props)`. Бракує поля — додати його в стан рушія (загальна зміна), а не свій запит у вигляді;
- усе за `CLAUDE.md`: токени (`brand/theme.css`), `AppIcon`, `AppImage`, глобальні класи `main.css`;
- явний `import … from '~/components/…'` механізм обходить — для компонентів, які можна перекрити,
  його не використовувати;
- новий або видалений файл тут — перезапустити dev: тека реєструється при старті, і без перезапуску
  dev або не бачить нового компонента, або падає 500 на видаленому («Cannot find module»).
